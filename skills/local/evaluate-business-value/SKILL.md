# 商业价值评估

帮助用户决定下一笔时间和资金投入。结论可支持继续、缩小范围、转向或停止，力度随证据变化。批判性体现为主动检验商业假设，并同等检查支持和反对继续投入的证据。

## 确定评估对象

先从当前对话与项目入口确认用户目标、目标市场、购买者、实际使用者、使用场景、开发阶段和资源约束。区分商业收入、内部降本、自用价值与学习收益。个人开发者和团队的时间均计入成本。

“日常工作”按项目实际场景解释，简短注明采用的解释。只有会改变结论的关键歧义才提问，提出一个带当前情景、已知信息和建议的问题。其余缺失数据记为未知，并继续完成可支持的判断。

## 核对项目与外部证据

- 有仓库时读取项目约束、当前产品规格、收费规则、进度与最近相关证据，再抽查核心入口及关键依赖的实现。按问题定向搜索，控制阅读范围。
- 分别记录已批准需求、代码存在、构建或集成验证、真机或生产观察、实际使用、真实付款。对过期记录、相互冲突的来源及抽查边界注明日期和影响。
- 使用公开产品页、官方价格与平台文档核验当前竞品、替代方式、模型能力、价格和分发条件。优先一手来源，引用支持具体陈述的页面，并注明厂商自报指标的性质。
- 有现成联网能力时直接使用。联网不可用时仍给出条件性评估，标明当前市场判断的证据缺口。
- 将用户断言作为待核验输入。将访谈、口头好评、持续主动使用、付费、续费、正贡献利润分别解释。

## 检查决定商业结果的因素

围绕最影响结论的因素展开，按项目需要选择深度。

| 因素 | 需要回答的问题 |
|---|---|
| 痛点与净收益 | 谁在何时遇到什么问题，频率和损失多大？节省的时间与错误，扣除配置、维护、纠错、等待和切换后还有多少？ |
| 替代方式 | 用户目前用系统自带能力、现有产品、人工流程或继续忍受问题，分别付出什么？迁移收益足够大吗？ |
| 使用与留存 | 谁购买、谁使用、谁承担新增工作？新鲜感消退后是否主动使用？需求是否随年龄、项目结束或流程变化而消失？ |
| 付费理由 | 哪项持续收益值得付费？免费与付费体验是否形成合理升级？竞争者的售价只能证明报价，销量、续费与利润各需证据。 |
| 获客与渠道 | 第一批用户从哪里来？销售周期、信任、安装和权限门槛多大？现有渠道能否重复获得目标客户？ |
| 交付与运营 | 核心承诺是否经过真实环境验证？平台权限、集成、客服、数据与审核要求对成本和上线有何具体影响？ |
| 竞争优势 | 模型或接口普及后，仍有哪些流程、集成、信任、渠道、数据使用权或验证结果能支撑差异？ |

## 单独评估 AI 与开发方式

同时检查 AI 对交付成本、竞品进入成本、功能替代性和用户预期的影响。结合当下可验证能力讨论模型准确率、延迟、重试、人工兜底与版本变化。

代码生成效率、完整交付效率、维护负担和市场需求分别判断。检查新增功能、文档和测试是否挤占了最关键的真实验证。将已经发生的投入记录为沉没成本，继续决策以新增成本和预期收益为依据。

对模型升级可能强化产品的路径，也给出成立条件。用端到端使用流程评估通用模型对产品的替代范围。

## 核算回报

有实际数据时计算单位经济性，注明单位、周期、币种和来源。变量不足时列出缺项，可使用明确标注的假设做敏感性分析。

- 每付费客户贡献 = 同周期净收入 − 模型、存储、通知、交易、退款损失及变动支持成本。每项成本只计一次。
- 获客回收期 = 获客成本 ÷ 每期客户贡献，仅在贡献为正时有意义。
- 覆盖固定成本所需客户数 = 同周期固定成本 ÷ 客户贡献，另外说明创始人时间成本是否计入。
- 活跃客户数、付费率和付费客户数保持口径一致。月付、年付和使用成本换算到同一周期。
- 内部工具核算实际采用人数、节省时间、时间可兑现程度和维护成本。自用项目按用户明确的预算与收益判断。

市场规模、估值、成功概率、收入预测与评分均需要依据。缺乏依据时直接说明未知，给出结论成立的条件。

## 交付评估

默认在对话中给出精简、可追溯的评估。按用户要求保存报告时采用项目约定的位置。评估建议与已批准产品行为分别记录，仓库修改按用户授权执行。

包含以下内容，可按任务规模合并。

1. 明确的投入建议与适用目标。
2. 支撑建议的关键项目证据和当前外部事实。
3. 最强的继续理由、最强的停止理由，以及足以推翻当前判断的反证。
4. 净使用价值、付费与获客逻辑、AI 竞争影响、回报约束中的主要问题。
5. 最小验证行动、预算或时间边界、观察指标和继续或停止条件。阈值结合阶段与样本解释，明确其为建议。
6. 当前未知、证据日期与核验范围。

验证行动优先针对足以改变决策的最大不确定性。平台关键能力、陌生用户主动使用、真实支付和续费，可分别形成不同阶段的证据。小样本结果支持下一轮决策的力度需明确说明。
