# 存量老项目接入、多工具实测验收与跨仓协同清单

仅在**接手已有老仓库接入治理**、**核验多工具规则加载**、或**多仓库跨端契约演进**时按需读取本文件。完整方法论见本仓 `docs/guides/` 下的上下文工程方案。

## 1. 存量老项目接入前：P0 只读盘点（先查清，不强拆目录）

对已有仓库引入规范或脚手架前，先执行只读盘点，不得先改文件或虚构命令：

1. **仓库形态与边界**：确认是单仓、Monorepo 还是多仓之一，记录上游/下游与无访问权仓库（标为 `NOT_ACCESSIBLE`）。
2. **既有 AI 规则与冲突**：搜索所有 `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`CLAUDE.local.md`、`CODEBUDDY.md`，识别可能遮蔽项目规则的祖先/本地文件。
3. **既有文档与正式契约**：盘点已有的架构文档、Spec、ADR、OpenAPI/Proto/GraphQL/JSON Schema 与 PR 模板；**优先在入口链接复用既有文档，绝不复制第二套真源**。
4. **真实构建与检查命令**：打开真实构建/CI 配置核实编译、测试、原生 Lint 命令，绝不根据文件存在与否猜测命令。
5. **敏感与权限边界**：盘点凭据、生产配置、迁移目录与需要保护的依赖清单，确认后再增量补充 `<project>/AGENTS.md`（或最小接入 `scripts/init-project-governance.sh`）。

输出盘点结论时明确区分「已核实事实 / 合理推断 / 待确认」三栏并附真实文件路径。

## 2. 多工具规则加载实测验收（I-01～I-05）

新项目建好或老项目接入后，不要假设写了 `AGENTS.md` 所有工具就已正确加载；对团队实际使用的工具（Antigravity / WorkBuddy / ZCode / Codex / Cursor / Claude Code / Copilot / OpenCode）执行 1 分钟实测：

- **I-01 根入口可达**：在新会话中确认宿主实际读取了项目根 `<project>/AGENTS.md`（或薄指针 `<project>/CLAUDE.md` / `<project>/.github/copilot-instructions.md`）并能复述 2 条项目专属规则。
- **I-02 无遮蔽冲突**：确认没有祖先目录 `CLAUDE.md`（如共享工作根目录副本）、`AGENTS.override.md` 或过时全局配置静默掩盖本项目规则。
- **I-03 多端路由生效**：对不自动扫子目录的工具（如 ZCode），确认模型能通过根 `AGENTS.md` 的多端路由表找到并读取对应 `<app>/AGENTS.md`。
- **I-04 规则可执行**：用一条无副作用规则（如“修改前先列出拟跑检查命令”）做只读演练，确认模型遵守。
- **I-05 无全量上下文膨胀**：确认会话启动仅加载精简入口，无关模块 Spec/文档未被整仓注入。

## 3. 大仓代码检索停止条件（防上下文膨胀）

在大型项目或老仓库中探索代码时，遵循 `文本/路径搜索 → 源码与配置 → 调用方/LSP → Git 历史 → 跨仓契约` 顺序；**同时满足以下条件即停止扩张读取范围，进入设计与修改**：

1. 已定位目标实现与必要直接调用方；
2. 已核对涉及的公开契约与已知消费者（不可访问方已显式记为未验证）；
3. 已确认受影响测试与可运行的真实校验命令；
4. 最可能的错误假设已通过一次反证检索排除；
5. 剩余不确定项不影响安全、可回滚的最小实现。

## 4. 多仓库跨端契约兼容发布顺序

当前后端、移动端、管理端分属**独立 Git 仓库**且接口需要破坏性演进（如字段更名/删除/语义变更）时，不得假设多个仓库能同时原子发布：

1. **确认唯一权威契约与 Owner**：以机器可读契约（OpenAPI / Proto / Schema）为真源，列出所有消费端及客户端最低兼容版本。
2. **阶段 1（提供方双兼容）**：提供方先同时兼容旧字段/旧协议与新字段/新协议，并完成回归测试上线。
3. **阶段 2（消费端逐步升级）**：各消费端按各自仓库完成适配、契约校验与发版。
4. **阶段 3（验证退出条件后清理）**：确认线上流量与客户端最低支持版本不再依赖旧契约后，再单独提交移除旧兼容逻辑；无法访问的消费端须在交付风险中显式标明未验证。
