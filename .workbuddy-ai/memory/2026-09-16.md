## 推送后 CI 全红：根因是测试不自洽

推 `641f348` 后 `gh run list` 显示失败（其实往前两次推送也是红的，CI 一直是红的）。
`gh run view <id> --log` 抓到的关键行：

```
FAIL message-human (expected success)
Commit attribution check failed: unable to read Git author identity.
FAIL message-co-authored-by (expected exit 1, got 2)
...
36 attribution checks failed.
```

其余三个套件在 CI 全绿（check-hook 3、check-version-bump 5、distribute 20）。

### 根因

`tests/check-commit-attribution.sh` 直接以 `--message` 模式调用检查器，而检查器会
`git var GIT_AUTHOR_IDENT` 读当前身份（第 138 行）。GitHub Actions runner：

- 没有 `user.name` / `user.email`（actions/checkout 不配）；
- 主机名不带域名（`fv-az...`），git 的自动探测因此失败，不会像 macOS 那样
  退化成 `user@Host.local`。

于是身份读不到 → 检查器按失败关闭返回 **2** → 所有 message 层用例集体误报
（`expected exit 1, got 2`；期望成功的则直接失败）。

**本机为什么不红**：`~/.gitconfig` 里有 `gaoyusheng`，而且本机主机名是 `Peanut.local`（带点）。

### 复现与修复

复现（本机也能重现，不必等 CI）：

```bash
env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null HOME=/tmp/ag-nohome \
    GIT_AUTHOR_NAME= GIT_AUTHOR_EMAIL= GIT_COMMITTER_NAME= GIT_COMMITTER_EMAIL= \
    bash tests/check-commit-attribution.sh
# 修复前：36 FAIL，首条 FAIL message-human
# 修复后：0 FAIL
```

修复两条：

1. 测试开头 `export` 一份**中性基线身份**（`Test Author <author@example.invalid>` 等），
   需要换身份的用例继续用 `env GIT_AUTHOR_NAME=...` 逐条覆盖。测试不再依赖任何环境身份。
2. 新增用例 `identity-unreadable-fails-closed`（期望退出 2），把「身份读不到就失败关闭」
   钉成契约 —— 空 `GIT_AUTHOR_NAME` 在任何平台都会让 `git var` 失败，所以这条同时是
   「测试不得依赖环境身份」的回归保护。

`VERSION` 1.10.0 → **1.10.1**（`tests/` 在 `RULE_PATHS` 里，改测试必须 bump，否则下次分发被
`check-version-bump.sh` 拦下）。

### 教训（写给下次）

- **本机跑绿 ≠ CI 跑绿。** 本地 git 全局配置和带域名的主机名掩盖了测试对环境的隐式依赖。
  写完测试要问一句：这条用例依赖哪些环境状态？换台机器还成立吗？
- 本仓 CI 之前一直是红的，说明**没人看 CI**。推送后应当 `gh run list` 确认，而不是假定通过。
- 模拟 CI 时不要用「把身份变量设为空」，那会让 fixture 里的 `git commit` 也失败，
  得到的是假故障；正确做法是 `env -u` 加 `GIT_CONFIG_GLOBAL=/dev/null`。
